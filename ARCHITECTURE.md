# Выбор архитектуры для преимущественно российских покупателей

Дата проверки источников: 13 октября 2026. Это инженерный выбор под небольшой каталог, а не обещание отсутствия любых сбоев. Доступ из сетей российских операторов из этой среды проверить нельзя.

## Сравнение

| Подход | Простой и обслуживание | Доступность и вывод |
| --- | --- | --- |
| Supabase Free | Может приостанавливать проекты с низкой активностью за 7 дней; нужны отдельные копии данных и фото | Не выбираем для редких обновлений и максимальной надёжности |
| Supabase Pro | Не приостанавливается из-за неактивности; платный сервис | Снимает проблему паузы, но не решает маршрутизацию/блокировки иностранных сервисов |
| Cloudflare Workers / D1 / R2 | Удобный управляемый стек без собственного VPS | Cloudflare подтверждает ограничения до первых 16 КБ у российских операторов; исключаем из production-пути |
| Yandex Object Storage + API Gateway + отдельный редактор | Управляемое хранилище с версиями, оплата объёма/операций; не требует работающего процесса БД для просмотра | Выбранный вариант: готовая статическая витрина и фотографии на российской инфраструктуре |
| Selectel S3 + статическая витрина | S3-совместимость упрощает резервирование и перенос; редактирование требует отдельного сервиса | Сильная альтернатива и кандидат для независимой резервной копии |
| Timeweb виртуальный хостинг + PHP/MySQL | Привычная панель, автоматические резервные копии файлов/БД; фиксированный платный тариф | Практичный более простой вариант. Для отказоустойчивого просмотра также стоит генерировать статическую витрину |
| PocketBase или Appwrite на российском VPS | Нет паузы бесплатного BaaS, но нужно следить за ОС, обновлениями, TLS, процессами, резервными копиями | Удобны функционально, но хуже соответствуют минимальному обслуживанию. PocketBase отдельно предупреждает о production-critical применении |

Достоверного измерения, какой провайдер «самый надёжный во всех сетях России», нет. Выбор Yandex — оценка архитектуры: российское размещение, управляемое хранилище и отсутствие зависимости просмотра от редактора. Учитывать аварии провайдера, баланс, DNS и ограничения отдельных сетей.

## Выбранный production-стек

1. React + Vite, локальные шрифты/системные шрифты и локальные ресурсы; без иностранных CDN в обязательном пути.
2. Yandex Object Storage: frontend, опубликованный catalog.json и фотографии. HTTPS на домене через API Gateway с object_storage-интеграцией, без Cloudflare proxy.
3. Отдельный приватный редактор + Node.js Cloud Functions. Серверная авторизация двух администраторов; ключи S3 только на сервере. Хранилище исходных данных закрытое. Черновики в публичный каталог не попадают.
4. После сохранения — валидация, запись новой версии каталога и замена готового снимка. Фотографии имеют неизменяемые случайные имена; сначала загрузить фото, затем обновить снимок. При ошибке публикации предыдущая витрина продолжает работать, редактор показывает необходимость повтора.
5. Версионирование бакета + отдельная копия у другого провайдера или локально. Версионирование в одном аккаунте не заменяет независимый бэкап. Проверять восстановление на отдельном закрытом окружении.
6. Публичный каталог не делает запросы в базу и не требует запуска редактора. Нет keep-alive/heartbeat ради предотвращения пауз. Cold start функции может задерживать редактирование, но не открытие каталога.

Платный российский production-хостинг не подключался. В историческом README требуется нулевой бюджет; мы не вводим оплачиваемые ресурсы без согласования. Полноценная надёжность не должна зависеть от временного trial или бесконечно бесплатного тарифа.

## Ёмкость

Для 500 изделий × 3–8 фото = 1500–4000 изображений. При среднем 250 КБ WebP это около 0.375–1 ГБ; при предельных 1.5 МБ — до 6 ГБ. Оригиналы 3 МБ × 1500–4000 = 4.5–12 ГБ. Две дополнительные независимые копии увеличат суммарный объём примерно втрое. Размеры расчётные, а не обещание фактического сжатия.

Рекомендуемые production-производные: 480/800 px для карточек и 1600 px для галереи. Карточки порциями по 24, ленивые изображения, полная галерея только после открытия. В прототипе реализован один оптимизированный размер до 1600 px; отдельные srcset-производные пока не реализованы.

500 карточек с текстом и URL фото обычно укладываются в несколько сотен килобайт — низкие единицы мегабайт. Не загружать изображения галерей в списке. Для значительно большего каталога разбить метаданные по страницам/категориям.

## Текущая реализация

Приватный прототип: React/Vinext + D1 (works/settings/uploads) + R2 (загруженные фото). Авторизацию владельца обеспечивает платформа Sites. Все изменения серверные, включая данные и фотографии. SQL миграции в drizzle. Фото начальных коллекций входят в source/build.

Это отдельное временное размещение для оценки UX. Российская инфраструктура, Cloud Functions-редактор и production-авторизация пока не развёрнуты. Нельзя обещать, что Sites-ссылка работает у российских покупателей без VPN. Пользователь запретил публичную публикацию; доступ остается только у владельца.
