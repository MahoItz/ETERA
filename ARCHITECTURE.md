# Архитектура Etera

## Runtime

Публичная витрина и административный редактор — одно Vite-приложение из `src/`, опубликованное на GitHub Pages. Данные и фотографии не попадают в git: клиент читает их из Supabase.

`src/catalog.ts` обращается к Supabase через RPC и таблицы с RLS. Сохранение работы выполняет атомарная функция `public.save_work`; она проверяет revision, сохраняет варианты по ID и оставляет receipt для безопасного повтора запроса.

## Данные и фотографии

Шапка витрины переключается в кабинете администратора: «Настройки сайта» → «Режим шапки». `site_settings.hero_mode` хранит общий для посетителей режим: `standard` (по умолчанию) или `new-year`. Обычная шапка показывает до 10 опубликованных непроданных работ с фотографиями, сначала избранные, затем новые. Стрелки, точки, клавиатура и свайпы переключают карточки; нажатие открывает работу. Автопрокрутка раз в 5 секунд останавливается при взаимодействии, открытом окне, скрытой вкладке, выходе шапки из области просмотра и настройке уменьшения движения. Оба режима используют одну сиреневую полоску `HeroValues` с общими стилями.

Фон обычной шапки — `public/images/hero-standard-background.webp` (горизонтальный WebP, желательно от 2400 × 1000, без текста и карточек). До добавления файла используется сливовый градиент. Новогодний фон остаётся в `public/images/hero-background.webp`.

- PostgreSQL: работы, варианты, категории, настройки и украшения.
- Supabase Storage bucket `work-photos`: загруженные WebP.
- Временные загрузки и удалённые ссылки проходят через `work_photo_cleanup`. Worker перед удалением повторно проверяет все ссылки на файл.
- SQL-источник схемы — только `supabase/migrations/`.

## Публикация

GitHub Actions выполняет `npm ci`, `npm run lint`, `npm test` и `npm run build`, после чего публикует `dist/` в GitHub Pages. Source map не публикуются.

Обязательные production-переменные: `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. Publishable key допустим в клиенте; service-role ключи и worker secrets остаются только в Supabase.

## Ссылки

GitHub Pages не требует SPA rewrite, поэтому карточки используют query URL: `?work=<slug>` и `?work=<slug>&variant=<slug>`. Slug транслитерируются и стабильно хранятся в БД.

Кабинет администратора открывается по `?account=admin` из меню аккаунта. Раздел «Обзор» получает агрегаты через `public.admin_dashboard(period_days)` для 7, 30 или 90 дней. Публичная функция работает с правами вызывающего; закрытая `private.admin_dashboard` проверяет `auth.uid()` и актуальную роль в `profiles`, затем считает регистрации по `auth.users.created_at` (без анонимных аккаунтов), текущие сохранения и популярные работы. Списки пользователей и чужое избранное клиенту не выдаются. Удалённые сохранения не считаются событиями; рейтинг использует все текущие сохранения независимо от периода. «Настройки сайта» использует существующее сохранение названия и контакта.

Проверки статистики и прав доступа: `npm run test:admin` (также входят в `npm test`).

В настройках контактов `contact` хранит Instagram для совместимости, отдельные поля `vk`, `telegram` и `phone` — остальные способы связи. Пустые контакты скрываются. Ссылки HTTP(S) и телефон доступны в карточках работ и блоке «О мастерской»; номер отображается с исходным форматированием, а ссылка `tel:` использует только цифры и начальный `+`.

## Переписка с мастером

Корзина покупателя хранится отдельно от избранного в `cart_items`; мастер видит только отправленные подборки. RPC `cart_add`, `cart_list` и `cart_submit` проверяют пользователя, точный вариант/набор и актуальную доступность. Отправка сохраняет серверный снимок фигурок в `chat_messages.selection` и открывает один диалог `kind = 'cart'` на покупателя. Изменения корзины и каталога не меняют отправленный состав. Подробнее, включая миграцию, откат и проверки: [docs/cart.md](docs/cart.md).

`chat_conversations` хранит одну переписку покупателя по каждой работе, `chat_messages` — текстовые сообщения, `chat_reads` — отдельную отметку прочтения для каждого участника. Удаление работы сохраняет переписку и снимок её названия. Покупатель читает свои сообщения через RLS, администраторы — обращения покупателей. Запись выполняют RPC `chat_send` и `chat_mark_read` через закрытые функции с проверкой текущего пользователя и роли. Клиентский UUID сообщения обеспечивает безопасный повтор после потери ответа. Отметка прочтения включает только загруженные сообщения, просмотренные в открытой переписке.

`chat_inbox` возвращает страницы по 50 диалогов и общее количество непрочитанных сообщений, включая диалоги за пределами страницы. Клиент подписывается на изменения `chat_messages` и собственных `chat_reads` через Supabase Realtime; резервный опрос обновляет открытый диалог раз в 7 секунд, уведомления — раз в 15 секунд, также при возвращении на вкладку. В скрытой вкладке опрос приостанавливается.

В карточке работы остаются кнопка «Написать мастеру» и альтернативные контакты. Кнопка открывает отдельное окно чата по этой работе: существующая переписка загружается автоматически, новая создаётся при первой отправке. После закрытия чата пользователь возвращается в карточку. Гость может набрать текст в окне чата и войти без потери черновика. Покупатель открывает все сообщения из колокольчика или меню аккаунта. Мастер читает и отвечает в разделе кабинета `?account=admin&section=messages`; уведомление может открыть конкретный диалог через параметр `conversation`. Проверки: `npm run test:chat` (также входят в `npm test`).

Кнопка удаления доступна в списке и открытом диалоге. После подтверждения `chat_delete` удаляет переписку, сообщения и отметки прочтения для обеих сторон; покупатель может удалить свою переписку, администратор — любую. Функция проверяет текущую роль и UUID последнего сообщения под блокировкой диалога: новое сообщение после открытия подтверждения отменяет удаление с ошибкой `40001`. Прямой DELETE для браузера закрыт. Повтор запроса уже удалённого диалога безопасен. Список периодически сверяет загруженные ID с базой, чтобы удалённые собеседником чаты исчезали из кэша и уведомлений; открытая переписка также проверяет доступность диалога и блокирует отправку после удаления.
