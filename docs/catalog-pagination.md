# Загрузка каталога (F13)

Витрина читает `public.catalog_cards` страницами по 24 работы. «Показать ещё» запрашивает следующий диапазон, а не повторно весь каталог. Поиск по названию, описанию и материалу, категория, статус и сортировка применяются на сервере до ограничения страницы. В конце сортировки добавлен ID для стабильного порядка при одинаковой цене, названии или дате. Результат содержит точное число найденных работ.

Страница содержит краткие поля, одну обложку, число фото и вариантов, а также вычисленную цену каталога. Описания, массивы фото и варианты не передаются. Цена набора берётся из работы; цена коллекции отдельных фигурок — минимальная известная цена непроданного варианта, включая нулевую. Неизвестная цена остаётся `null` и при сортировке по возрастанию находится в конце.

Полная работа из `works` с фотографиями и вариантами запрашивается по ID или slug при открытии карточки либо редактора. Краткая запись не передаётся редактору для сохранения. Полные данные сохраняются в памяти для повторного просмотра; обновлённая ревизия краткой записи сбрасывает старый кеш деталей.

Шапка запрашивает только необходимые работы: до 10 для обычной карусели или работы, связанные с украшениями ёлки. Избранное загружает краткие записи по своим ID при открытии кабинета. Корзина открывает товар по ID из серверного снимка даже за пределами просмотренных страниц. Общий список для административных редакторов загружается краткими страницами только при их открытии.

Ошибки следующей страницы сохраняют уже показанные работы. Ошибки фильтра или карточки имеют отдельное действие повтора. Устаревшие ответы отменяются при смене фильтра, закрытии карточки и смене состояния аккаунта. Быстрый повторный клик на «Показать ещё» не запускает параллельную загрузку того же диапазона.

## Миграция и публикация

Миграция [20261114094959_catalog_card_pagination.sql](../supabase/migrations/20261114094959_catalog_card_pagination.sql) применена к production-проекту `bznkcwgklcodoseeqaet` 14.11.2026 через Supabase MCP; версия удалённой истории — `20261114102122`, имя — `catalog_card_pagination`. Повторно применять к этому проекту не нужно. Для нового окружения она должна быть применена до публикации клиента. Миграция добавляет read-only представление `catalog_cards`; строки существующих таблиц не изменяются.

Представление использует `security_invoker`, поэтому действует RLS исходных таблиц. Гостям и покупателям недоступны черновики, архив и проданные работы, включая прямой запрос по ID. Административные запросы используют текущую роль базы; клиентский параметр фильтра не предоставляет дополнительных прав. Итоги популярности берутся из существующей функции `favorite_counts()`, без раскрытия владельцев избранного.

После применения миграции опубликовать клиент обычным workflow. Откат клиента не требует удаления представления. Проверено на production после миграции: `security_invoker=true`, права только на чтение для anon/authenticated, 35 доступных работ для anon и отсутствие скрытых работ. Публичный REST API вернул страницы 24 и 11 записей с точным общим числом 35, без дублей. Новых замечаний Security Advisor нет. Клиент в рамках применения миграции не публиковался.

## Превью изображений

`CatalogImage` поддерживает `srcSet`/`sizes`. Для карточек, обычной карусели и миниатюр галерей предусмотрены размеры 160, 320, 640 и 960 px. Основное изображение товара и полноэкранный просмотр используют оригинал.

Генерация размеров через Supabase Storage включается явно:

```dotenv
VITE_SUPABASE_IMAGE_TRANSFORMS=true
```

В GitHub Actions это одноимённая repository variable (Settings → Secrets and variables → Actions → Variables). По умолчанию значение `false`, изображения загружаются как раньше. Согласно [документации Supabase](https://supabase.com/docs/guides/storage/serving/image-transformations), преобразования доступны на Pro и выше; они не включаются автоматически и тариф не меняется. Поэтому уменьшение реальных файлов изображений на текущем production-тарифе не заявляется.

Для локальных, blob/data- и посторонних URL преобразования не строятся. Если преобразование не удалось, компонент убирает `srcSet` и загружает оригинал, затем при необходимости использует существующий ограниченный механизм повторных запросов. Отключение флага возвращает оригиналы без изменения данных каталога.

## Проверки

```sh
npm test
npm run test:catalog-pages
npm run test:security
npm run build
npm run lint
```

Новые SQL-тесты используют настоящие миграции в PGlite: 61 опубликованная работа с 20 фото у каждой, границы страниц, порядок и фильтры, цены, глобальная популярность, RLS и запрет записи через представление. Проверка добавлена в workflow публикации.

Браузерная регрессия: [tests/catalog-pages.browser.js](../tests/catalog-pages.browser.js). Для проверки responsive-изображений запустить локальный Vite с `VITE_SUPABASE_IMAGE_TRANSFORMS=true`, затем выполнить команды из начала файла. Все внешние запросы в регрессии имитируются, включая успешные и неуспешные преобразования изображений. Отдельно адаптированы прежние проверки цены набора, устойчивости каталога, доступности, читаемости, входа, лайков и CSP.
