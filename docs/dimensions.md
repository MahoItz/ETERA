# Размеры фигурок

Для работы и каждого варианта можно указать высоту, ширину и глубину. Пустые
направления не показываются. У отдельной фигурки размеры самостоятельны:
размеры всего набора ей не подставляются. Переключение см/мм пересчитывает
значения, а не меняет их смысл.
Поддерживаются точка, запятая и точность до 0,001 мм; нулевые и отрицательные
размеры не принимаются.

`works.measurements` и `variants.measurements` содержат `heightMm`, `widthMm`,
`depthMm` и `unit`. Числа всегда в миллиметрах, `unit` задаёт единицы отображения.
Отсутствие всех размеров представлено SQL NULL. Ограничения БД проверяют форму,
диапазон и точность. Поле `dimensions` сохранено для старых текстовых записей:
направления по ним не угадываются. Новая структурированная запись заменяет
старый текст при сохранении через редактор.

`dimension_suggestions` — общая история положительных значений в мм. Её читают
и меняют только администраторы (RLS). Первичный ключ убирает физические дубли
и поддерживает числовую сортировку. Триггеры пополняют историю при сохранении
нового или изменённого размера в той же транзакции, что и `save_work`.
Удаление подсказки не меняет работу. Сохранение неизменённого размера, включая
переключение единиц, не восстанавливает удалённую подсказку. Повторный ввод этого
размера в другую работу запомнит его снова. В редакторе доступно «Вернуть».

Старые размеры с явным обозначением см/мм добавлены в историю при миграции,
без попыток определить высоту, ширину и глубину. Записи без единиц не разбираются.
Старые клиенты, не передающие `measurements`, не стирают новые размеры.

Проверки: `npm test`, `npm run build`. Скрипт
`tests/measurements.verify.sql` проверяет настоящий RPC под ролью администратора
и откатывает все тестовые записи, историю и квитанции сохранения.
