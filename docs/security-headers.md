# Защитные заголовки (F08)

Статус: конфигурация подготовлена; применение на production ожидает выбора CDN/прокси.

На 14.11.2026 `https://elveria.ru/` обслуживается напрямую GitHub Pages, а NS домена принадлежат Timeweb. В ответе HTTP 200 отсутствуют CSP и X-Frame-Options. Настройки DNS сами по себе не добавляют HTTP-заголовки. GitHub Pages не применяет конфигурацию Nginx или файл `_headers`.

`frame-ancestors` работает только в HTTP-заголовке CSP. Его нельзя заменить meta-тегом, JavaScript-проверкой родительского окна или настройками Vite preview. Поэтому F08 нельзя считать завершённым до применения и проверки заголовков на публичном домене.

## Подготовка для конкретной сборки

```sh
npm run build
npm run security:headers
```

Скрипт читает готовый `dist/index.html` и `VITE_SUPABASE_URL` из production-окружения/`.env.local`. Ключи Supabase в конфигурацию не включаются. Создаются два локальных файла:

- `.local/security-headers/headers.json` — точные имена и значения HTTP-заголовков для CDN/прокси.
- `.local/security-headers/nginx.conf` — директивы `add_header ... always` для существующего HTTPS server/location Nginx.

Файлы не публикуются в GitHub Pages и не меняют инфраструктуру. Для Nginx include нужно установить в том контексте, который фактически отдаёт HTML; наличие других `add_header` в дочерних location может изменить наследование. Перенос сайта, DNS, сертификаты, upstream и маршрутизация здесь не настраиваются.

## Политика

- `frame-ancestors 'none'` и `X-Frame-Options: DENY` запрещают любое встраивание, включая тот же origin.
- `script-src` разрешает скрипты своего origin и SHA-256 каждого встроенного скрипта готового HTML. Это сохраняет ранний обработчик восстановления устаревших ресурсов; `unsafe-inline` и `unsafe-eval` для JavaScript не разрешены.
- Изображения: свой origin, точный HTTPS origin backend, `data:` для декоративного SVG и `blob:` для предпросмотра загрузок.
- Соединения: свой origin, точный HTTPS origin backend и его WSS endpoint для Realtime.
- CSS: свой origin и встроенные стили, необходимые существующим галереям, анимациям и блокировке прокрутки диалогов. Это послабление относится к стилям.
- `default-src 'none'`, запрет объектов, дочерних фреймов и изменения base URL; отправка HTML-форм ограничена своим origin.
- Дополнительно: `nosniff`, `strict-origin-when-cross-origin` и запрет камеры, микрофона и геолокации.

Источники изображений за пределами указанного backend намеренно не разрешены. При их появлении нужно отдельно расширить политику после проверки источника.

Хеш встроенного скрипта зависит от его содержимого после нормализации переводов строк HTML-парсером (CRLF/CR → LF). Заголовки должны соответствовать публикуемой сборке, в том числе при откате. Если CDN одновременно обслуживает старый и новый HTML, на время перехода нужно разрешать оба проверенных хеша либо публиковать HTML и заголовки атомарно. Нельзя минифицировать/переписывать встроенный скрипт на CDN без пересчёта хеша.

## Применение и проверка

На выбранном CDN/прокси установить значения из `headers.json` в режиме замены заголовка, а не добавления второго CSP. Применять к HTML на всех маршрутах и с query-параметрами, без кэширования пользовательских ответов backend через этот прокси. GitHub Pages может остаться источником статических файлов.

После настройки:

```sh
npm run security:verify -- https://elveria.ru/
npm run security:verify -- 'https://elveria.ru/?work=example'
```

Проверка запрашивает HTML по HTTPS и сравнивает реальные заголовки с политикой для полученного HTML и настроенного backend. Она завершается с ошибкой при отсутствии или несовпадении заголовков. Далее в браузере проверить загрузку витрины и изображений, вход, регистрацию, восстановление, галерею, blob-предпросмотр редактора и переписку/Realtime. Реальные операции с аккаунтами и production-данными требуют отдельного тестового сценария. Проверить отказ встраивания с постороннего origin и отсутствие непредусмотренных `securitypolicyviolation` в обычных сценариях.

Локальная браузерная регрессия с настоящими HTTP-заголовками и имитацией внешних запросов:

```sh
npm run build
npm run security:headers
node tests/security-headers-server.mjs
```

В другом терминале:

```sh
playwright-cli open http://127.0.0.1:4188 --browser=chrome
playwright-cli run-code --filename=tests/security-headers.browser.js
npm run security:verify -- http://127.0.0.1:4188/
```

Сервер теста слушает только loopback, порты 4188 и 4189. Регрессия проверяет обе шапки на 320 и 1440 px, открытие форм авторизации и галерей, data/blob-изображения, исполнение разрешённого скрипта восстановления, отказ выполнения посторонних скриптов и отказ встраивания с того же и другого origin. Она не выполняет настоящий вход, загрузку файлов или отправку сообщений.

Только после успешной проверки публичного домена отметить F08 выполненным в аудите.
