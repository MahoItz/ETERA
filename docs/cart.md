# Корзина и обращения с подборкой

Корзина доступна покупателю после входа: кнопка в шапке и раздел личного кабинета. Избранное остаётся отдельным списком. Для коллекций нужно выбрать конкретную фигурку; наборы добавляются целиком. Повторное добавление не создаёт дубль. Количество отдельных позиций ограничено 50; желаемое число экземпляров можно указать в комментарии мастеру.

`cart_items` хранит приватный список пользователя. Запись выполняет `cart_add`, чтение с актуальной доступностью и ценами — `cart_list`, удаление — DELETE с RLS по владельцу. Прямая вставка и изменение строк закрыты. Гости и анонимные Auth-пользователи не могут добавлять и отправлять подборки. Мастер не читает чужие неотправленные корзины.

`cart_submit(request_id, item_ids, message_body)` принимает только ID показанных пользователю позиций, проверяет владельца и наличие в каталоге, создаёт сообщение с серверным снимком фигурок. Вложение `chat_messages.selection` содержит названия, варианты, фото, цены на момент отправки и ссылки на карточки. ID позиций сохраняются для проверки повторных запросов. Комментарий ограничен 2000 символами. После отправки корзина остаётся доступной для дальнейшего выбора.

Один диалог `chat_conversations.kind = 'cart'` на покупателя объединяет отправленные подборки и ответы мастера. Обычные диалоги по работам сохраняют `kind = 'work'`. Используются существующие уведомления, непрочитанные сообщения, Realtime, резервный опрос и удаление диалога. Удаление диалога удаляет вложения вместе с сообщениями для обеих сторон.

Снимки в корзине сохраняются при удалении фигурки/варианта, чтобы пользователь видел и мог удалить недоступную позицию. Отправка недоступной позиции блокируется. Снимки в сообщениях не меняются при редактировании каталога и корзины. Это обращение для обсуждения, без оплаты, резервирования или гарантии цены. Фото остаются ссылками на Storage: после удаления исходного файла вместо фото отображается штатная заглушка.

## Внедрение

1. Применить миграцию `20261026131038_customer_cart.sql` к Etera.
2. Проверить функции, grants, RLS и security advisors.
3. Опубликовать новую сборку приложения. Старый клиент совместим с добавленными колонками.

## Откат

Вернуть предыдущую сборку фронтенда. Новые таблица, функции и колонки могут оставаться в базе: старый клиент их не использует. Такой откат сохраняет корзины и отправленные подборки. Удалять новые объекты или переписки для отката не требуется. Полное удаление схемы выполнять отдельно, только после экспорта данных и согласования их потери.

## Проверка

`npm run test:cart`, `npm run lint`, `npm test`, `npm run build`.

Для проверки в Supabase выполнить `tests/cart.verify.sql` от владельца БД. Сценарий использует существующих покупателя и администратора, все тестовые изменения откатывает; сообщения не публикуются в Realtime.

Вручную: войти покупателем, добавить работу и вариант другой работы, обновить страницу, удалить одну позицию, отправить подборку с комментарием. В кабинете мастера открыть «Сообщения», проверить состав и ответить. Другой покупатель не должен видеть ни корзину, ни переписку. Удаление позиции после отправки не должно изменять вложение в чате. Повторить на узком экране.
