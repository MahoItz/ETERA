# Восстановление пароля

В окне «Вход» под полем пароля есть кнопка «Забыли пароль?». Она открывает форму отправки письма через `supabase.auth.resetPasswordForEmail`. Ответ пользователю одинаковый для существующего и неизвестного email.

После успешного запроса повторная отправка в этой форме доступна через 60 секунд. Ошибки ограничения частоты запросов показываются по-русски.

Письмо возвращает пользователя на `https://elveria.ru/?auth=recovery`. Это query URL, поэтому GitHub Pages не требует настройки маршрутов. Для локальной разработки адрес строится от текущего origin и базового пути Vite.

В Supabase → Authentication → URL Configuration:

- Site URL: `https://elveria.ru/`.
- Добавьте в Redirect URLs точный адрес `https://elveria.ru/?auth=recovery`.
- Для локальных проверок с настоящей отправкой писем добавьте аналогичный URL с используемым локальным портом.

В Authentication → Email Templates → Reset Password установите содержимое `supabase/templates/reset-password.html`. Тема: «Восстановление пароля — Elveria». Ссылка в шаблоне должна оставаться `{{ .ConfirmationURL }}`: она проверяет токен через Supabase перед возвращением на сайт.

Приложение использует стандартный implicit flow браузерного Supabase-клиента. Оно запоминает признак восстановления до того, как SDK уберёт токены из URL, ожидает инициализации сессии и открывает форму нового пароля. Метка `auth=recovery` позволяет продолжить после перезагрузки страницы. Ошибка в ссылке блокирует смену пароля даже при наличии другой сохранённой сессии.

Форма проверяет длину от 6 символов и совпадение двух полей. Дополнительные требования Auth применяет на сервере; ошибки слабого или прежнего пароля показываются по-русски. Пароль сохраняется через `supabase.auth.updateUser`. После успеха поля очищаются, данные аккаунта обновляются. При закрытии формы из URL удаляются параметры восстановления, токены и ошибки.

Проверки: `node --experimental-strip-types --test tests/password-recovery.test.ts`, `npm run lint`, `npm run build`.
