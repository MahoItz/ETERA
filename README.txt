======================================================================
1. НАЗНАЧЕНИЕ ПРОЕКТА
======================================================================

Сайт создаётся для мастера, который вручную изготавливает фигурки,
украшения и другие декоративные изделия из гипса и бетона.

Сейчас главная задача — красивое, удобное портфолио-каталог,
где посетители могут рассматривать работы, характеристики и фотографии.
В будущем возможны продажи, однако полноценный интернет-магазин
на первом этапе не требуется.

Посетители преимущественно находятся в России. Сайт полностью
на русском языке. Основной источник аудитории — Instagram;
желательно также предусмотреть базовую индексацию поисковиками.

Ключевые приоритеты:
- Нулевой бюджет: использовать бесплатные сервисы и тарифы.
- Надёжность и доступность сайта, в том числе при редких обновлениях.
- Удобное управление с телефона или планшета без навыков программирования.
- Хорошая мобильная версия и качественная подача фотографий.
- Возможность дальнейшего расширения без полной переделки проекта.

======================================================================
2. УТВЕРЖДЁННЫЙ ТЕХНОЛОГИЧЕСКИЙ СТЕК
======================================================================

- React — пользовательский интерфейс.
- Vite — локальная разработка и production-сборка.
- GitHub — репозиторий исходного кода.
- GitHub Pages — бесплатный хостинг собранного фронтенда.
- GitHub Actions — автоматическая сборка и деплой из ветки main.
- Supabase PostgreSQL — данные каталога.
- Supabase Storage — фотографии.
- Supabase Auth — вход администратора.
- Supabase Row Level Security (RLS) — ограничения доступа.
- Адаптивный CSS — стили; конкретная организация CSS пока не утверждена.

Принцип работы:
1) Посетитель открывает статическое React-приложение на GitHub Pages.
2) Приложение получает опубликованные изделия и изображения из Supabase.
3) Администратор входит в защищённый режим редактирования на сайте.
4) Администратор меняет контент, данные сохраняются непосредственно в Supabase.
5) Изменения каталога видны на сайте без нового деплоя GitHub Pages.

При публикации на GitHub Pages учесть base path Vite, маршрутизацию
React (в том числе прямое открытие внутренних URL и обновление страницы),
а также настройку GitHub Actions. Не считать, что серверных функций
у GitHub Pages есть: приложение статическое.

ВАЖНЫЕ ОГРАНИЧЕНИЯ:
- Бесплатный Supabase может приостановить проект при низкой активности.
  Регулярные обновления мастером НЕ гарантируются. Полностью решить это
  одним фронтендом нельзя; решать будем позже.
- Бесплатный Supabase Storage ограничен по объёму и трафику.
  Предполагается каталог на сотни изделий, обычно по 3–8 фотографий.
  Нужна оптимизация изображений и возможность будущей миграции.
- Доступность внешних сервисов из России нужно учитывать и тестировать.
  Не вводить зависимость от Cloudflare как обязательную часть проекта.
- GitHub Pages рассчитан не на полноценный интернет-магазин:
  портфолио с контактами — текущая задача; если основной целью станут
  коммерческие сделки, потребуется повторно оценить правила GitHub
  Pages и, возможно, перенести хостинг.

======================================================================
3. ПУБЛИЧНАЯ ЧАСТЬ САЙТА
======================================================================

3.1. Основные возможности
- Главная страница, представляющая мастера и его работы.
- Каталог изделий с отдельными карточками.
- Подробный просмотр изделия с несколькими фотографиями.
- Категории, по которым можно просматривать работы.
- Сортировка: по новизне, названию, цене.
- Возможность закреплять избранные изделия выше остальных.
- Адаптивный интерфейс для мобильных устройств, планшетов и ПК.
- Ссылка на Instagram для связи по поводу изделий и заказов.
- Возможность отображать цену: цена необязательна, отсутствующая
  цена не должна выглядеть как «0».
- Базовые SEO-настройки: корректные title, description, изображения,
  семантическая разметка. Более глубокий SEO-подход обсудить позднее.

3.2. Данные изделия
- Название.
- Описание.
- Категория.
- Несколько фотографий и их порядок.
- Размеры.
- Материал (например, гипс или бетон).
- Вес.
- Цвета.
- Возможность изготовления под заказ.
- Необязательная цена. Если цена не указана, то ничего не отображается
- Статус наличия/доступности.
- Признак избранного/закреплённого изделия.
- Дата создания/публикации для сортировки.

Поля характеристик стоит делать необязательными там, где это логично:
мастер не обязан указывать все характеристики для каждого изделия.

3.3. Варианты одного изделия
Одна карточка может содержать несколько вариантов, например:
- окрашенный;
- неокрашенный.

Для вариантов могут различаться фотографии и цены. Следует
предусмотреть возможность отдельных характеристик/статуса наличия
по варианту, если это потребуется, без дублирования всей карточки.

3.4. Статусы
Не смешивать разные понятия:
- Статус публикации: черновик / опубликовано / скрыто (архив).
- Доступность: в наличии / под заказ / продано (конкретную модель
  статусов уточнить перед реализацией).
- Тип отделки: окрашенный / неокрашенный — это вариант изделия,
  а не его доступность.

Проданные изделия не показываются в публичном каталоге, но остаются
доступны администратору. При этом нужно учесть возможность того, что
один вариант продан, а другой ещё доступен.

======================================================================
4. АДМИНИСТРИРОВАНИЕ
======================================================================

Управление должно быть максимально простым для человека без
технических знаний и прежде всего удобным на смартфоне и планшете.

Предпочтительный UX — редактирование непосредственно на сайте:
после авторизации у карточек появляются действия «Добавить»,
«Редактировать», «Скрыть/архивировать», «Удалить» (если нужно).
При этом отдельный раздел для управления большим каталогом допустим,
если так будет заметно удобнее.

Функции администратора:
- Вход и выход из защищённого режима.
- Добавление и изменение изделий.
- Загрузка нескольких фотографий с устройства.
- Изменение порядка фотографий, удаление/замена отдельных фотографий.
- Создание и изменение вариантов окраски с разными ценами и фото.
- Управление характеристиками, ценой, наличием и статусами.
- Создание, переименование, сортировка и удаление категорий.
- Черновики (желательная, но не критичная функция).
- Скрытие проданных изделий из публичного каталога.
- Управление закреплёнными/избранными изделиями.
- Доступ к архиву ранее скрытых или проданных работ.

Фотографии желательно оптимизировать автоматически в браузере
перед загрузкой (уменьшение слишком больших изображений, сжатие,
поддерживаемый формат и сохранение достаточного качества).
Следует предусмотреть проверку типов/размеров файлов и понятные
сообщения об ошибках загрузки.

Администраторов фактически двое: автор изделий (мастер) и разработчик.
Изначально высказано пожелание использовать один общий аккаунт ради
простоты. Два раздельных аккаунта с одинаковыми правами безопаснее;
конкретный вариант входа окончательно не утверждён. Архитектура
должна позволять независимые аккаунты и не требовать хранения
паролей в коде.

БЕЗОПАСНОСТЬ:
- Публичным посетителям разрешён только просмотр опубликованных,
  не скрытых и допустимых к показу данных.
- Создавать, редактировать и удалять могут только администраторы.
- Ограничения должны действовать на стороне Supabase (RLS и политики
  Storage), а не только через скрытые кнопки в React.
- Никогда не помещать service_role key или другие секреты в сборку
  фронтенда либо в репозиторий. Использовать разрешённый публичный
  ключ с корректными политиками RLS.
- Удаление категории или изображения не должно случайно разрушать
  другие связанные данные.

5. ВИЗУАЛЬНОЕ НАПРАВЛЕНИЕ
======================================================================

Стиль — сочетание минимализма и тёплой ремесленной эстетики:
- Светлый фон, много свободного пространства.
- Нейтральные бежевые, молочные, натуральные оттенки.
- Крупные качественные фотографии, акцент на фактуре изделий.
- Удобочитаемые заголовки, спокойная типографика.
- Лёгкий, современный и аккуратный интерфейс с красивыми соверменными анимациями.
- Мобильный дизайн не менее важен, чем десктопный.

Пока нет названия бренда, логотипа и утверждённых фирменных цветов.
Временно можно использовать рабочее текстовое название, которое
легко заменить позже. Дизайн будет уточняться по ходу проекта,
в том числе на основе реальных фотографий изделий.
